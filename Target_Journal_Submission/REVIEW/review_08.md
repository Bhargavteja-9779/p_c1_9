# Review 08: R8-reproducibility

**Recommendation:** major_revision

**Summary:** The analysis pipeline is genuinely reproducible: analyze.py regenerates results/metrics.json and results/statistics.json bit-for-bit from the committed raw CSVs, tables regenerate identically (git tree stays clean), figures/tables read only from machine-readable result files (no hand-entered numbers), 11 unit tests pass, seeds are set and runs are checkpointed/resumable, and the headline numbers (0.51% aggregate spread, 0.10x orbit SD, 0.032/36%/91% train-aug reduction, -0.0001 test-orbit p=0.8, 0.102 shortcut drop p=5e-10, invariance table 0.084/0.119/0.071/0.425, leakage 82/2832/851) all trace correctly to the result files. However, the manuscript, README, and requirements describe a protocol and environment that were not actually executed: it claims four model families (incl. a Nystrom SVM that was dropped) and five seeds, when the code and committed data used three models and three seeds; the pinned package versions do not match the versions that produced the results; and two results are mis-reported (Section 6.4 contradicts its own table; the shortcut headline pools non-commensurable units). These are fixable, mostly by correcting text to match the executed run, but they currently make the paper non-reproducible as described and internally contradictory.

## Findings

### [MAJOR] Protocol vs. executed run (manuscript/README contradict code and data)
- **Issue:** The manuscript Section 5 states 'four model families: gradient-boosted trees (LightGBM), random forests, an RBF-kernel SVM via Nystrom approximation, and a linear model' and 'Each configuration is run with five seeds'; README says 'the full study uses seeds 0-4'. The code and committed results used only THREE models and THREE seeds. src/training/grid.py: MODELS = ['lgbm','rf','linear']  # svm(Nystroem) dropped: costly, least informative; full-mode seeds=[0,1,2], method_seeds=[0,1,2], shortcut_seeds=[0,1,2]. results/experiment_logs/run_meta_full.json and raw_results.csv confirm models={lgbm,linear,rf}, seeds={0,1,2}; RQ1 n_cells=330 = 55 datasets x 3 models x 2 feats (no SVM). The SVM is described in detail and unit-tested but never appears in any result. The abstract and contributions say '3 model families', directly contradicting Section 5's 'four'. This is also an undisclosed deviation from the pre-registration (research_plan.md: '5 model families', 'R = 5 scaffold resplits (seeds 0-4)', 'R = 10 for the headline SORB and RQ2'); the 2026-11-16 amendment reframes the headline but does not document the model/seed reduction.
- **Evidence:** A reader cannot reproduce 'four model families, five seeds' from the repo; run_all.py only produces three models and three seeds. The manuscript's stated methods thus do not match the released code or the numbers in metrics.json, and the abstract/Section 5 disagree on the model count.
- **Fix:** Correct Section 5 to 'three model families' (LightGBM, random forest, linear) and 'three seeds (0-2)'; remove the Nystrom-SVM description or explicitly state it was implemented but dropped from the reported grid; fix README 'seeds 0-4' -> 'seeds 0-2' and the layout note that lists Nystroem-SVM; and add a 'deviations from pre-registration' note. Alternatively, to honor the pre-registration, actually run the 5-seed/4-model grid (new experiment). The text-only correction requires no new experiment.
- **Requires new experiment:** False

### [MODERATE] Environment pinning (requirements.txt / environment.yml do not match run environment)
- **Issue:** requirements.txt is commented 'Versions pinned to what the study was run with' and pins numpy==2.5.3 and scipy==1.18.1, but the environment that actually produced the results has numpy 2.3.5 and scipy 1.17.1 (verified via importlib.metadata in the container). numpy 2.5.3 does not appear to exist in this environment's package set (the installed 2.x line tops out at 2.3.5), so `pip install -r requirements.txt` would either fail to resolve or install a different version than was used, breaking the determinism claim. environment.yml repeats the mismatched numpy=2.5/scipy=1.18 pins.
- **Evidence:** Pinned numpy==2.5.3/scipy==1.18.1 vs. actually-used numpy 2.3.5/scipy 1.17.1. A third party following the README cannot recreate the exact environment, undermining 'Determinism: fixed seeds; results cached' and 'environment specifications ... released'.
- **Fix:** Regenerate requirements.txt and environment.yml from an exact `pip freeze` / `conda env export` of the machine that produced results/*.csv, verify every pin installs cleanly from a clean venv, and (if feasible) confirm run_all.py --mode quick + analyze reproduce the cached cells under those pins.
- **Requires new experiment:** False

### [MODERATE] Results reporting: Section 6.4 contradicts its own Table (tbl:inv)
- **Issue:** Section 6.4 states the orbit SD 'is smallest for gradient-boosted trees on fingerprints (0.12x of the label SD) and largest for linear models on fingerprints (0.42x...)'. The paper's own Table tbl:inv (and metrics.json RQ5_invariance) show lgbm/desc=0.084 and linear/desc=0.071, both SMALLER than lgbm/ecfp=0.119. So 0.12x is not the smallest value; the minimum is linear-on-descriptors (0.071).
- **Evidence:** The sentence mis-ranks the four cells against the adjacent table, which a careful reviewer/reader will catch as an internal inconsistency and which weakens the 'representation-dependent' narrative.
- **Fix:** Reword to e.g. 'smallest for descriptor-based models (~0.07-0.08x) and, among fingerprint models, smallest for gradient-boosted trees (0.12x) and largest for linear models (0.42x)'.
- **Requires new experiment:** False

### [MODERATE] Code/statistics correctness: shortcut headline pools non-commensurable units
- **Issue:** Section 7.3's headline 'accuracy ... dropping by 0.102 in the primary metric (median over datasets)' is computed in analyze.rq5b_shortcut as pooled.baseline_shortcut_drop.median() over all 49 datasets, i.e. a single median taken across 40 regression RMSE drops AND 9 classification AUROC drops. src/training/shortcut.py computes baseline_shortcut_drop as a raw RMSE difference for regression (not normalized by label SD, unlike the invariance analysis which uses *_rel_sd) and an AUROC difference for classification. Per-task the drops are reg median 0.1128 (RMSE, in each dataset's own label units, unnormalized across datasets with very different label scales) vs clf median 0.0342 (AUROC); the pooled 0.102 is dominated by, and mostly inherits the arbitrary scale of, the regression RMSE values.
- **Evidence:** A median over mixed RMSE-and-AUROC quantities (and over RMSE values on datasets with incomparable label ranges) is not an interpretable single effect size; '0.102 in the primary metric' conflates units. Contrast the invariance metric, which the authors correctly normalize by label SD.
- **Fix:** Report the shortcut drop separately for regression and classification, and normalize the regression drop by each dataset's label SD (a dimensionless relative drop) before taking any median, mirroring the orbit_mean_rel_sd convention. The label SDs are available from the dataset loaders, so this is a re-analysis of existing shortcut_results.csv, not a new experiment.
- **Requires new experiment:** False

### [MINOR] Hardware/runtime claims vs. run metadata
- **Issue:** Section 9 states 'All experiments run on four CPU cores without a GPU' and README says 'Tested on 4 cores' and 'full study (~2-3 h wall on 4 cores)', but results/experiment_logs/run_meta_full.json records nproc=2 for the actual full run. Parallelism does not affect the (deterministic) numbers, only wall time, but the stated hardware/runtime is inaccurate.
- **Evidence:** run_meta_full.json: {'mode':'full','nproc':2,...}. The '4 cores / ~2-3 h' figures were not what the committed run used.
- **Fix:** State the actual core count (2) used for the released run, or note explicitly that core count affects only wall-clock time and not results; adjust the runtime estimate accordingly.
- **Requires new experiment:** False

### [MINOR] Undisclosed pre-registration deviations (orbit size, headline repeats)
- **Issue:** research_plan.md pre-registers orbit 'bounded to <= O members, O default 8' and 'R = 10 for the headline SORB and RQ2', whereas the executed run uses OrbitConfig(max_members=6) (manuscript M=6) and three seeds throughout. The manuscript is self-consistent on M=6, but these reductions from the pre-registered plan are not disclosed as deviations.
- **Evidence:** run_all.py ORBIT_CFG max_members=6 vs pre-reg O=8; three seeds vs pre-reg R=10 headline. Transparent pre-registration is a stated value of the paper (amendment says deviations are 'reported transparently'), so silent changes weaken that claim.
- **Fix:** Add a brief 'Deviations from pre-registration' paragraph listing the orbit-size (8->6), model-set (5->3 families), and repeat-count (5/10->3 seeds) changes and the rationale (CPU budget).
- **Requires new experiment:** False
