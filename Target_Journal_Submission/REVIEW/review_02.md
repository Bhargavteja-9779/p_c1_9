# Review 02: R2-methodology

**Recommendation:** major_revision

**Summary:** The core construction (standardization orbit, train-aug + test-time averaging, orbit-prediction-SD metric, semi-synthetic shortcut) is sensible and mostly sound, but two methodological problems undermine the central quantitative claims. First, the "standardization orbit" includes transformations that are NOT label-invariant for the endpoints studied (pH-7.4 protonation vs neutral, and stereo-stripping), so for logD/solubility/permeability/enantioselective potency the measured orbit spread partly reflects a REAL property dependence rather than "spurious" model sensitivity, and SORB enforces a partially false invariance. Second, the headline invariance statistic pools regression orbit-SD (normalized by label SD, dimensionless) with classification orbit-SD (raw predicted-probability SD, scale=1) and reports the mixture as "× the label standard deviation," which is a units error affecting the 0.10×/0.12×/0.42× numbers. Several smaller issues (non-matched test sets for the accuracy-neutrality test, trivial-by-construction framing of test-orbit invariance with an unquantified deployment gap, unjustified top-k tautomer pruning, featurization-sensitivity confound in the metric) are fixable by reanalysis or small experiments. Classification probabilities are handled correctly; ECE uses a biased equal-width estimator but is only a secondary diagnostic.

## Findings

### [MAJOR] Orbit definition / Problem formulation (Sec 3, 4.1; standardize.py standardization_orbit; Limitation ii)
- **Issue:** The standardization orbit is treated as a set of label-invariant representations, but standardization_orbit() (standardize.py L259-268) adds the pH-7.4 protonated form AND the neutralized form AND the stereo-stripped form as orbit members. Protonation state is physically determinative of exactly the endpoints in the benchmark set (lipophilicity/logD, aqueous solubility, permeability, plasma-protein binding are all pH/charge dependent), and stereo-stripping merges enantiomers/diastereomers that genuinely differ for enantioselective ADMET/potency endpoints. Thus the per-molecule prediction SD across the orbit (the paper's central 'violation' metric, _orbit_invariance in invariance.py) partly measures a REAL, correct property dependence the model learned, not 'spurious' sensitivity — yet every unit is claimed spurious (Sec 6.4: 'every unit of this spread is spurious'). Correspondingly, SORB forces equal predictions over genuinely different species, which degrades correctness rather than improving reliability. Limitation (ii) asserts invariance 'holds for the physicochemical and ADMET endpoints used,' which is false for the pH/charge-dependent and stereo-dependent endpoints that dominate the collection.
- **Evidence:** standardize.py OrbitConfig defaults include include_ph74, include_neutral, include_stripstereo all True; standardization_orbit adds op_protonate_ph74(smiles), op_neutralize(bmol), and op_strip_stereo(bmol) as members. The modeled endpoints include MoleculeNet Lipophilicity (logD at pH 7.4) and TDC ADMET (solubility, Caco-2/PAMPA permeability, PPBR) whose measured value is defined at a specific pH and therefore differs between the charged and neutral orbit members. RQ3 (metrics.json) reports +ph74 and +stripstereo aggregate deltas of 0.0, but that is the AGGREGATE-metric ablation; the contribution of the protonation and stereo axes to the per-molecule ORBIT SD (the headline quantity) is never decomposed, so the 'spurious' interpretation is unsupported where those axes contribute.
- **Fix:** Restrict the invariance orbit to operations that are genuinely label-invariant for the chosen endpoints (tautomer interconversion, aromaticity model, salt/fragment choice, SMILES-level notation), and move protonation and stereochemistry out of the default orbit or treat them per-endpoint. At minimum, decompose the orbit-prediction-SD by axis (tautomer vs protonation vs stereo vs aromaticity) using the existing cached orbits and report how much of the 0.10-0.42× comes from the property-determining axes; restate Limitation (ii) accurately and exclude pH/charge-defined endpoints from the 'invariance-violation' framing or analyze them separately.
- **Requires new experiment:** True

### [MAJOR] Headline invariance statistic (Abstract; Sec 6.4; analyze.py method_pooled L199-207, rq5_invariance L152-155; invariance.py _orbit_invariance + run_method_cell scale)
- **Issue:** The headline 'orbit prediction SD = 0.10× (overall), 0.12× (GBT), 0.42× (linear) of the label SD' pools regression and classification rows that are on different scales. In run_method_cell, scale = std(y[train]) for regression but scale = 1.0 for classification; _orbit_invariance divides the orbit prediction SD by this scale. So regression orbit_mean_rel_sd is a dimensionless fraction of the label SD, whereas classification orbit_mean_rel_sd is the raw SD of predicted P(y=1) (0-1 units), NOT normalized by the label SD. analyze.py then takes medians of orbit_mean_rel_sd pooled over both tasks (method_pooled L199-201 has no task filter; rq5 representation table L152-154 groups only by model×feat), and the manuscript labels the result '× the label standard deviation.' The two quantities are not commensurable and should not be pooled or jointly labeled.
- **Evidence:** Direct computation on method_results.csv: baseline orbit_mean_rel_sd median is 0.122 for reg (label-SD-normalized) but 0.033 for clf (raw probability SD, label_sd column = 1.0 for all clf rows). Pooled method_pooled trainaug_invariance baseline_median = 0.106 (metrics.json) mixes these; the clf contribution is mislabeled '× label SD.' The '36% relative reduction' and frac_reduced are likewise pooled across incommensurable units.
- **Fix:** Normalize classification orbit SD by its own label SD (e.g., sqrt(p(1-p)) of the training labels) so both tasks are dimensionless, OR report regression and classification invariance separately throughout (Abstract, Sec 6.4, Table 2, rq5 tables). Recompute the headline 0.10×/0.12×/0.42× and the 36% reduction per task. This is a pure re-aggregation of existing results.
- **Requires new experiment:** False

### [MODERATE] Accuracy-neutrality of test-orbit/full (Sec 7.1-7.2; invariance.py run_method_cell L80-108; analyze.py method_pooled L189-197)
- **Issue:** The central 'test-time averaging is accuracy-neutral' claim (median change -0.0001 RMSE, Wilcoxon p=0.8) is computed by pairing the baseline primary metric measured on the FULL test set against the SORB-testorbit/full metric measured on a random subset capped at ACC_CAP=600 molecules. For method datasets (<=6000 molecules, 80/20 split => test up to ~1200), datasets whose test set exceeds 600 have the two arms evaluated on different instance sets, so the paired Wilcoxon and the per-dataset delta are not apples-to-apples and carry extra subsampling noise.
- **Evidence:** run_method_cell: baseline row uses _acc(..., y[te], predict(base, Xcanon[te])) on the full test index te (L97); sorb_testorbit/sorb_full use sc = est.predict(cap_smi,...) with cap = te subsampled to ACC_CAP=600 (L80), scored against y[cap] (L104-108). method_pooled (L189-192) merges baseline and variant metrics by dataset×model×feat and subtracts them, so baseline-on-full is differenced against testorbit-on-cap whenever |te|>600.
- **Fix:** Evaluate baseline (and sorb_trainaug) on the identical capped subset used for the orbit-averaged variants before computing the paired deltas and Wilcoxon tests; or raise/remove the cap. Cheap re-run from the existing harness; recompute RQ4 accuracy rows.
- **Requires new experiment:** False

### [MODERATE] Test-orbit 'enforces invariance' (Abstract; Sec 4.2, 7.1, 10; sorb.py predict; standardize.py standardization_orbit L233)
- **Issue:** Test-time orbit averaging is invariant only tautologically: within the experiment each molecule has one precomputed orbit (dataset_orbits keyed on raw SMILES), so the averaged prediction is a single fixed value and orbit-SD is identically 0 by construction (correctly, the code records no invariance stat for it: inv_model=None). This is a definitional property, not an empirical finding, and should be stated as such rather than listed among SORB's contributions. More importantly, the deployment claim ('drop-in inference wrapper makes a model's prediction (nearly) independent of input standardization') is only approximate and the residual is never measured: standardization_orbit builds the orbit from base = P_rdkit(presented_smiles), and P_rdkit does largest-fragment+neutralize but NOT canonical-tautomer, so presenting two different tautomers of the same compound yields different base forms, different orbits, and different averaged predictions.
- **Evidence:** standardize.py L233: base = NAMED_PIPELINES['P_rdkit'].apply(smiles); P_rdkit (L179) has canonical_tautomer=False. Orbit membership (tautomer enumeration from bmol, L253-254) therefore depends on which tautomer was presented. sorb.py predict averages over that presentation-dependent orbit. The manuscript hedges with '(nearly)' (Sec 4.2, 7.1) but never quantifies the residual prediction SD of the wrapper across presentations.
- **Fix:** State plainly that in-sample test-orbit invariance is exact by construction (not an empirical result). For the deployment claim, construct the inference orbit from a canonical-tautomer (presentation-independent) base so the orbit is identical regardless of input standardization, and empirically measure the residual prediction SD of the test-orbit wrapper when the SAME molecule is presented under each named pipeline.
- **Requires new experiment:** True

### [MODERATE] Tautomer-score pruning / orbit boundedness (Sec 4.1; standardize.py enumerate_tautomers L121-139, OrbitConfig max_tautomers)
- **Issue:** The orbit's tautomer members are the top-k (max_tautomers=3 in run_all.py) distinct tautomers ranked by RDKit's canonicalization score, with no energy/population threshold and no justification that this set equals the chemically co-existing forms. The manuscript states implausible forms 'are excluded' by the ranking, but enumerate_tautomers applies no plausibility threshold — it simply truncates to k, so exclusion is incidental to rank, not guaranteed (a molecule with many close-scoring plausible tautomers loses real members; a molecule with one dominant tautomer may retain implausible high-energy members 2-3 that are NOT chemically equivalent). The central magnitude (0.42×) can depend on this arbitrary k, yet only 'qualitative' robustness is claimed (Sec 8, Table S4).
- **Evidence:** standardize.py enumerate_tautomers L128-137 ranks by tautomer_score and returns scored[:max_forms] with no threshold; the docstring's 'naturally downranked and excluded' is not enforced. tautomer_score (L110-118) is exactly RDKit's canonical-tautomer scoring, so the 'plausibility' pruning is circular with how the canonical member is chosen.
- **Fix:** Define orbit membership with a principled criterion (score-gap or relative-population/energy threshold, or a tautomer-fraction cutoff) rather than a fixed top-k; verify no implausible tautomer survives the cut. Report the MAGNITUDE sensitivity of the headline orbit-SD to max_tautomers and max_members quantitatively (not just 'qualitatively unchanged').
- **Requires new experiment:** True

### [MODERATE] Interpretation of orbit-prediction-SD (Sec 3, 6.4; invariance.py _orbit_invariance)
- **Issue:** The orbit-prediction-SD is presented as a model property ('standardization sensitivity'), but it is largely a measure of how much the FEATURIZATION changes across the orbit (which the authors choose) propagated through the model. The pre-registration itself concedes it is '>0 by construction unless the featurization is already invariant' (research_plan.md L150-151), yet this is not disclosed in the manuscript. Consequently the flagship 'representation-dependent' result (linear+fingerprint most sensitive, trees least) is partly a restatement of the generic fact that linear models respond continuously to input perturbations while tree ensembles are piecewise-constant — not a discovery specific to standardization. The mean is also computed over all test molecules including singleton-orbit molecules whose SD is 0 by construction (~5-8% of molecules), so the magnitude depends on orbit-composition as well.
- **Evidence:** _orbit_invariance (invariance.py L53-66) returns SD of predict_scores over cached orbit featurizations with no normalization for the magnitude of feature change across the orbit; singleton/short orbits append sds=0.0 (L59). research_plan.md L150-151 explicitly notes the metric is positive 'by construction' from featurization differences.
- **Fix:** Disclose in the manuscript that the metric reflects featurization-change-through-model and is positive by construction. Add a control that separates 'how much features change' from 'how much the model amplifies it' — e.g., report prediction SD relative to the orbit's feature-space spread, or benchmark against a featurization-invariant reference — so the representation-dependence claim is not confounded with generic model smoothness. Report the metric restricted to molecules with non-trivial orbits.
- **Requires new experiment:** False

### [MINOR] Classification probability / ECE handling (metrics.py classification_metrics, expected_calibration_error; zoo.py predict_scores; invariance.py _acc)
- **Issue:** Classification probabilities are handled correctly overall: predict_scores returns P(y=1) via predict_proba (sigmoid fallback only for the dropped SVM path), and orbit averaging takes the mean probability, which is a valid ensemble; AUROC/AUPRC/Brier use the score, hard-label metrics threshold at 0.5. The only weakness is that ECE uses an equal-WIDTH 15-bin estimator, which is known to be biased and high-variance on the imbalanced TDC ADMET classification sets (sparsely populated high-probability bins). ECE is a secondary diagnostic (not in the headline), so impact is limited.
- **Evidence:** metrics.py expected_calibration_error L37-47 uses np.linspace(0,1,n_bins+1) equal-width bins; many TDC clf endpoints have prevalence far from 0.5, leaving extreme bins underpopulated and the ECE estimate unstable.
- **Fix:** Use equal-mass (adaptive) binning or a debiased ECE estimator, and confirm ECE for SORB variants is computed on the orbit-averaged probabilities (not single-member). State the binning scheme in the SI.
- **Requires new experiment:** False
