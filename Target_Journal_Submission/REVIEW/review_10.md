# Review 10: R10-hostile (competing researcher / final adversarial)

**Recommendation:** reject

**Summary:** The core thesis — "aggregate metrics robust, per-prediction not, therefore use SORB" — survives the shallow "it's just ensemble averaging" objection (the per-prediction orbit SD is genuine model sensitivity to different fingerprints, not an averaging artifact). But the paper collapses under a deeper attack: the entire "violation" is manufactured by comparing against a strawman baseline (P_rdkit) that deliberately omits tautomer canonicalization — the very operation RQ3 identifies as dominant — while the authors already implement deterministic canonical-tautomer standardization in canonical_identity() and use it for deduplication. A canonical-tautomer-once pipeline collapses the orbit to a single point, yielding EXACT invariance at 1x inference cost, dominating SORB-testorbit (approximate invariance, 6x cost) on every axis; this essential baseline is never run, so the paper's claim that invariance requires SORB is unsupported, and the work reduces to "preprocessing matters, use a consistent canonical pipeline." Compounding this are verifiable integrity defects: the manuscript claims "five seeds" and "four model families including an RBF-kernel SVM," but every result file contains only three seeds (0,1,2) and three models (lgbm/linear/rf) with no SVM anywhere; the testorbit reliability benefit is asserted but never measured; and the "benefits tree learners / accuracy-neutral" claim is contradicted by the authors' own significance tests.

## Findings

### [FATAL] Core contribution / Method necessity (Sec 4, 6.4, 7.1)
- **Issue:** The central claim that standardization-invariance 'requires' SORB is established only against a baseline (P_rdkit = largest-fragment + neutralize) that OMITS tautomer canonicalization, which RQ3 (metrics.json RQ3_ablation: +tautomer is the only non-zero operation, 0.006) identifies as the dominant driver of the orbit spread. The authors already implement a deterministic canonical-tautomer standardizer (standardize.py op_canonical_tautomer, used in canonical_identity() for dedup), which collapses the orbit's tautomer axis to a single point. A 'canonical-tautomer-once' pipeline (applied identically to train and test) therefore yields EXACT invariance to input presentation at 1x inference cost with no new convention, strictly dominating SORB-testorbit (approximate, order-truncated, 6x cost). This obvious, cheaper, exactly-invariant baseline is never evaluated, so the paper's core premise ('the silent confounder requires a remedy') and the recommendation of test-time orbit averaging as 'the safe universal default' are unsupported. The work reduces to the known advice 'use a consistent canonical pipeline.'
- **Evidence:** run_method_cell (invariance.py L78,96): baseline trained on features(...,'P_rdkit',...), i.e. no tautomer canonicalization. NAMED_PIPELINES['P_rdkit'] has canonical_tautomer=False (standardize.py L179). canonical_identity() (L200-214) DOES apply op_canonical_tautomer, proving the authors have an orbit-collapsing canonicalizer in hand but chose a baseline that omits it. RQ3 shows tautomer is the sole material operation. No experiment trains+tests a canonical-tautomer model and measures its residual orbit SD (which would be ~0 on the dominant axis).
- **Fix:** Add a canonical-tautomer-once baseline (P_taut-style: fix tautomer + one protonation + one aromaticity model, applied to train and test) and report its per-prediction orbit SD and accuracy against SORB-testorbit. SORB can only be a contribution if it beats this baseline on reliability-at-equal-cost or on accuracy; otherwise reframe the paper as a reporting-protocol/diagnosis paper and drop the SORB-necessity claims.
- **Requires new experiment:** True

### [MAJOR] Experimental Setup (Sec 5, L185-187) vs result files
- **Issue:** Section 5 states the study uses 'four model families: gradient-boosted trees (LightGBM), random forests, an RBF-kernel SVM via Nyström approximation, and a linear model.' No SVM appears in ANY result file (raw_results/ablation/method/shortcut models = {lgbm, linear, rf} only). The pre-registration also listed SVM and a tiny MLP consistency variant. Separately, the Abstract/Contributions/Conclusion say '3 model families,' internally contradicting Section 5's 'four.' This is a methodology claim (an RBF-kernel SVM) for which no evidence exists in the released results.
- **Evidence:** grep of manuscript L19/71/381 ('3 model families') vs L185-186 ('four model families ... RBF-kernel SVM via Nystrom'). CSV scan: raw_results/ablation_results models={lgbm,linear,rf}; method_results/shortcut_results models={lgbm,linear}. 'SVM'/'Nystrom' appears nowhere in results. MLP consistency variant (claimed in Sec 4.2/SI) likewise absent.
- **Fix:** Either run the SVM (and MLP) and include results, or delete every claim of an SVM/MLP model family and reconcile the model-family count throughout (it is 3: lgbm, linear, rf). State explicitly which models were actually run for each RQ.
- **Requires new experiment:** True

### [MAJOR] Statistics / reproducibility (Sec 5, L211)
- **Issue:** Section 5 states 'Each configuration is run with five seeds,' and the pre-registration specified R=5 for the grid and R=10 for the headline SORB/RQ2 comparisons. Every result file contains only seeds {0,1,2} = three seeds. The SORB section (L294) quietly says 'three seeds' while Section 5 says 'five' — an internal contradiction and an undisclosed, unexplained deviation from both the stated methods and the pre-registration that reduces statistical power on the headline null results.
- **Evidence:** CSV seed scan: raw_results/method_results/shortcut_results/ablation_results all = {'0','1','2'}. Manuscript L211 'five seeds' vs L294 'three seeds'. research_plan.md L120-121: 'R = 5 scaffold resplits ... R = 10 for the headline SORB and RQ2 comparisons.' The pre-registration amendment does not mention reducing seeds.
- **Fix:** Correct Section 5 to the true seed count, run the pre-registered seed counts (5 grid / 10 headline) or explicitly justify the reduction as a disclosed deviation, and re-derive all p-values/CIs. Note that under-seeding directly weakens the non-significant 'accuracy-neutral' claims (see next finding).
- **Requires new experiment:** True

### [MAJOR] SORB error analysis (Sec 7.1-7.2, L300-318)
- **Issue:** The paper claims training augmentation 'benefits robust (tree-based) learners' and that 'for the gradient-boosted-tree learner it is roughly accuracy-neutral.' The authors' own per-cell statistics show lgbm training augmentation SIGNIFICANTLY WORSENS regression RMSE on both featurizations: lgbm/ecfp/reg median -0.0148, p=5.8e-6, improved on only 22.5% of datasets; lgbm/desc/reg median -0.0101, p=0.02, improved on 35%. Pooled regression trainaug is significantly worse (metrics.json reg_sorb_trainaug median -0.013, p=5.1e-8, 32% improved). Trainaug is positive only on classification and only non-significantly. The 'benefits tree learners / accuracy-neutral for GBDT' framing is directly contradicted by the significance tests.
- **Evidence:** statistics.json: lgbm/ecfp/reg/sorb_trainaug median_improvement -0.01483, wilcoxon_p 5.8e-6, frac_improved 0.225; lgbm/desc/reg/sorb_trainaug median -0.01006, p=0.0200, frac 0.35. metrics.json RQ4_method_pooled.reg_sorb_trainaug: median -0.013, p=5.1e-8, frac_improved 0.319.
- **Fix:** Rewrite Sec 7.1-7.2 to state that trainaug significantly degrades tree-learner regression accuracy (not neutral), and restrict any accuracy-positive claim to the specific (classification, non-significant) cells. Do not describe a significantly-worse result (p=5.8e-6) as 'roughly accuracy-neutral.'
- **Requires new experiment:** False

### [MAJOR] Test-orbit 'free reliability' claim (Sec 7.1, L298-300)
- **Issue:** 'Accuracy-neutral,' 'no significant accuracy cost,' and 'a free reliability improvement' are all inferred from NON-significant Wilcoxon tests (reg testorbit p=0.8, clf p=0.90). Failing to reject the null is not evidence of equivalence; no equivalence test (e.g., TOST) or negligibility margin is specified. The per-cell CIs are wide and include non-negligible accuracy harm: lgbm/ecfp/reg/testorbit RMSE-change CI = [-0.0077, +0.1446] and lgbm/desc/reg/testorbit CI upper = +0.1029 — i.e., up to ~0.14 RMSE degradation is consistent with the data. 'Accuracy-neutral' is therefore unestablished.
- **Evidence:** statistics.json: lgbm/ecfp/reg/sorb_testorbit ci_lo -0.0077, ci_hi 0.1446; lgbm/desc/reg/sorb_testorbit ci_hi 0.1029; linear/ecfp/reg/sorb_testorbit mean +0.315, ci_hi 0.629. metrics.json reg_sorb_testorbit p=0.805. Manuscript L298-300 asserts neutrality from p=0.8.
- **Fix:** Replace null-acceptance language with a formal equivalence test against a pre-stated negligibility margin (e.g., fraction of label SD), and report that for several model/featurization cells the CI admits meaningful accuracy loss. More seeds (see seed finding) will tighten these CIs.
- **Requires new experiment:** False

### [MAJOR] Test-orbit 'enforces invariance' (Abstract; Sec 4.2; Sec 7.1)
- **Issue:** The reliability benefit of SORB-testorbit — the paper's recommended universal default — is asserted 'by construction' but never measured: in run_method_cell the invariance metrics (_pipeline_matrix/_orbit_invariance) are computed only for the baseline and trainaug rows; for sorb_testorbit and sorb_full, base_row is called with inv_model=None, so no orbit SD is recorded for the averaged predictor. Worse, the construction does not actually guarantee the claimed invariance 'to which member was presented': standardization_orbit() is seeded by the presented SMILES (member[0] = P_rdkit(smiles), which does NOT canonicalize tautomers), and the member list is truncated to max_members in insertion order, so two chemically-equivalent input tautomers generate different (order-truncated) orbits and therefore different averages. The abstract's 'makes the output independent of which member was presented' is false as implemented (true only in the unrealized 'complete orbit' limit).
- **Evidence:** invariance.py L104-108: for ('sorb_testorbit', base) and ('sorb_full', ...), base_row(method, _acc(...), None) -> inv_model=None, so orbit SD never computed for averaged variants. standardize.py L233 base=P_rdkit.apply(smiles) (no canonical_tautomer), L269 members[:cfg.max_members] (order-dependent truncation). No experiment presents the same molecule as different input forms and checks that the testorbit average is invariant.
- **Fix:** Directly measure cross-presentation invariance of SORB-testorbit: for each test molecule, generate the orbit from several different starting members, average each, and report the residual SD of the averaged prediction (should be ~0 if the claim holds). Fix the orbit construction to be canonicalization-seeded (start from the canonical-tautomer identity, not P_rdkit) so the orbit is genuinely input-independent, or soften the 'enforces invariance' claim to 'reduces, but does not eliminate, presentation dependence.'
- **Requires new experiment:** True

### [MAJOR] Headline effect size (Abstract; Sec 6.4)
- **Issue:** The alarming headline figure (orbit SD up to 0.42x label SD) is for linear-on-ECFP — a high-variance model essentially nobody deploys for production QSAR, which the paper itself calls the most unstable learner. For the recommended/most-used model (LightGBM) the orbit SD is 0.084x (desc) to 0.119x (ecfp) of the label SD, which the paper concedes is 'comparable to a fraction of experimental assay noise' (~0.3-0.5 log units for potency). The 'material irreproducibility' narrative is driven by a strawman worst case; for the models practitioners actually use, the effect is at or below assay noise, undercutting the urgency.
- **Evidence:** metrics.json RQ5_invariance: lgbm/desc 0.0843, lgbm/ecfp 0.1191, linear/desc 0.0715, linear/ecfp 0.4247. Manuscript L257-265 concedes 'comparable to a fraction of experimental assay noise.' The 0.42x worst case is linear/ecfp only.
- **Fix:** Lead with the effect for deployed models (trees), state explicitly that the 0.42x case is a high-variance linear model not used in practice, and quantify the orbit SD against measured assay reproducibility per endpoint so readers can judge materiality. Temper 'material irreproducibility' accordingly.
- **Requires new experiment:** False

### [MODERATE] Semi-synthetic shortcut experiment (Sec 7.3; shortcut.py)
- **Issue:** The 'controlled validation' is near-tautological: the standardization shortcut is INJECTED by construction (shortcut.py _present() picks orbit member by the true label), so a model that averages over the orbit (destroying the injected correlation) cannot exploit it 'by construction' — SORB wins because the experiment is built so it must. It provides no evidence that naturally-occurring standardization leaks into real labels. Moreover the framing 'accuracy collapses when the shortcut is removed' overstates: the counterfactual baseline is only 0.016 worse than the honest model (median baseline_cf_vs_honest=0.016), i.e., removing the injected leak returns the model to ~honest performance; the 0.102 'drop' is measured against the artificially inflated biased number, not against honest accuracy.
- **Evidence:** shortcut.py L33-42 _present() selects member by hi_mask (true label). metrics.json RQ5b: median_baseline_shortcut_drop 0.1022 (biased->cf) but median_baseline_cf_vs_honest only 0.0164 (cf vs honest). So counterfactual accuracy ~ honest; the 'collapse' is loss of inflated accuracy, not degradation below honest.
- **Fix:** Either (a) demonstrate NATURAL standardization-label leakage in real benchmarks (e.g., whether provider standardization state correlates with labels), which would be a genuine finding, or (b) downgrade Sec 7.3 to an illustrative sanity check and remove 'confirms that standard models exploit standardization as a shortcut,' clarifying that the shortcut is injected and that counterfactual accuracy returns to honest baseline.
- **Requires new experiment:** True

### [MODERATE] Robustness/Generalization (Sec 8, L336; Sec 7)
- **Issue:** SORB and the shortcut experiments ran on 49 datasets (<=6000 molecules) and only 2 models (lgbm, linear), but Section 8 claims the findings are consistent '(iv) across the 55 datasets,' and the headline invariance table (Tbl inv) reports only lgbm and linear, omitting random forests (the other 'tree ensemble') despite the paper's repeated 'tree ensembles are least sensitive' messaging resting on trees. The method-section 'across datasets' statements never disclose n=49 or the 2-model restriction.
- **Evidence:** method_results/shortcut_results: n_datasets=49, models={lgbm,linear}. Manuscript L336 'across the 55 datasets' (SORB). RQ5_invariance table (metrics.json) has only lgbm/linear x desc/ecfp; rf absent though raw_results includes rf. Sec 7.1 'across datasets (three seeds)' gives no n.
- **Fix:** State the SORB/shortcut evaluation scope explicitly (49 datasets <=6000 mols; models lgbm and linear only), correct 'across the 55 datasets' in Sec 8, and either add RF to the SORB/invariance evaluation or stop citing RF robustness in method claims.
- **Requires new experiment:** False

### [MODERATE] The 'silent confounder' framing (Sec 6.2 vs 6.4)
- **Issue:** The rhetorical contrast 'aggregate robust, per-prediction not' compares two quantities that cannot reflect each other by construction: the aggregate metric is computed with every molecule in ONE internally-consistent pipeline (so per-molecule shifts cancel across the test set), while the orbit SD deliberately varies each molecule across its orbit. The aggregate metric is 'blind' to orbit variance tautologically, because orbit members are never fed into the aggregate. The scenario that would actually move the aggregate — each test molecule presented as an independently/randomly drawn orbit member (a lab that standardizes inconsistently per-compound) — is not directly tested; the reported pipeline SD (0.004-0.029 relative) stays tiny only because each pipeline is internally consistent, so it does not probe the per-molecule-random case.
- **Evidence:** invariance.py _pipeline_matrix presents whole-dataset pipelines (consistent per pipeline); _inv_stats/_orbit_invariance present per-molecule orbits. No configuration evaluates aggregate accuracy under per-molecule random orbit draws. metrics.json RQ1 pipe SD 0.004-0.0286 (consistent pipelines) vs orbit SD 0.07-0.42.
- **Fix:** Add an aggregate-under-random-per-molecule-standardization experiment to show whether/when inconsistent per-compound standardization degrades aggregate metrics; otherwise temper the 'aggregate metrics hide it' claim to acknowledge it is a definitional consequence of measuring aggregate under one consistent pipeline.
- **Requires new experiment:** True

### [MINOR] Abstract/Table consistency
- **Issue:** Model-family count is stated as both '3' (Abstract L19, Contributions L71, Conclusion L381) and 'four' (Sec 5 L185); and headline invariance numbers appear as '0.10x median' (text) vs table values that round differently (0.084-0.119 for trees, 0.425 for linear/ecfp). The abstract's '3 model families' happens to match the 3 models actually run, which further exposes the Section-5 'four (incl. SVM)' claim as spurious.
- **Evidence:** Manuscript L19/71/381 '3 model families' vs L185 'four model families.' Table inv values 0.084/0.119/0.071/0.425 vs abstract 'up to 0.42x' and 'median 0.10x.'
- **Fix:** Reconcile the model-family count to the true value (3: lgbm, linear, rf) throughout, and ensure every quoted statistic matches the result files exactly.
- **Requires new experiment:** False
