# Review 06: R6-magnitude (Effect Magnitude & Robustness)

**Recommendation:** major_revision

**Summary:** The core phenomenon (nonzero per-prediction standardization sensitivity) is real and cleanly measured, but the headline magnitude is overstated relative to what realistic standardization practice produces, and the manuscript's robustness claims are not backed by data. The paper headlines the standardization-ORBIT prediction SD (0.10-0.42x label SD) and frames it as the between-laboratory reproducibility gap, yet the paper's own realistic named-pipeline SD - exactly the "two labs apply different valid pipelines" scenario - is 14-17x smaller (0.004-0.034x label SD, ~0.009-0.034 log units) and is tabulated without interpretation. Separately, Section 8 asserts the findings hold under random splits and that orbit-size/tautomer-count were varied, but the grid only ran scaffold splits and the cited SI (random-split replication, Table S4, Figures S1-S4) is an empty placeholder. These must be resolved before the magnitude/robustness claims can stand.

## Findings

### [FATAL] Robustness - random splits claimed but never run
- **Issue:** Section 5 lists random splits as a robustness check and Section 8 states 'We verify that the findings are not artifacts of a single protocol. The invariance violation and SORB's effect are consistent under (i) random instead of scaffold splits', citing SI Figures S1-S4. In fact the production grid hardcodes split="scaffold" (code/src/training/grid.py:25-30), every result row in raw_results.csv/method_results.csv/ablation_results.csv carries split=scaffold (5940/2352/2970 rows, 0 random), and supplementary/supplementary.md S7 'Random-split replication ... (Table S4)' is an unfilled skeleton header with no figures S1-S4 on disk. The affirmative robustness claim and its SI references describe experiments that were not performed.
- **Evidence:** grid.py:26,30 set split="scaffold" for quick and full runs; a Counter over all four result CSVs returns split={'scaffold': ...} only and seeds {0,1,2}; supplementary.md is 39 lines of placeholders ({{N_DATASETS}}) with S7 naming random-split/orbit-size sensitivity but containing no tables or numbers; code/figures/ holds only the 5 main figures, no S1-S4. The magnitude is plausibly split-dependent: random splits reduce train/test distribution shift and would change both baseline accuracy and the orbit SD, so this is a load-bearing, not cosmetic, check.
- **Fix:** Either actually run the full grid (and the SORB and orbit-size analyses) under random splits and populate S7/Table S4/Figures S1-S4 with real numbers, or delete every claim of random-split robustness (Section 5 'with random splits as a robustness check', Section 8 item (i)) and the orbit-size/tautomer-count sensitivity claim. Do not cite SI exhibits that do not exist.
- **Requires new experiment:** True

### [MAJOR] Headline magnitude relies on orbit SD, not realistic-pipeline SD
- **Issue:** The abstract, Section 6.4, and Conclusion headline the standardization-ORBIT prediction SD (median 0.10x, up to 0.42x label SD) and the Introduction/Section 3 frame it as what 'two laboratories that download the same benchmark and apply different but equally valid standardizations' would experience. But that two-labs scenario is precisely the realistic named-pipeline SD, which the paper measured and reports in Table 2 as 0.0040-0.0286x label SD - 14-17x smaller - and never discusses in the text. The orbit is deliberately more diverse than any single deterministic pipeline (it enumerates up to 4 alternative tautomers plus protonation/stereo/aromaticity variants and measures spread across all of them, whereas every realistic pipeline selects ONE canonical tautomer; standardize.py:121-139, 228-269). The headline therefore reports a near-upper-bound while the practically-relevant quantity is an order of magnitude smaller.
- **Evidence:** From method_results.csv (baseline): lgbm/ecfp median orbit rel-SD 0.129 vs pipeline rel-SD 0.0075 (ratio 17.3x), i.e. 0.169 vs 0.009 absolute log units; linear/ecfp 0.481 vs 0.034 (ratio 14x). metrics.json RQ5_invariance lists pipe_mean_rel_sd 0.004-0.0286 alongside orbit 0.084-0.425. The abstract and Section 6.4 quote only the orbit numbers; the pipeline column in Table 2 (tbl:inv) is presented with zero interpretation and never appears in the narrative.
- **Fix:** Reframe the magnitude claim as a range bounded below by the realistic-pipeline SD and above by the orbit SD, and interpret the pipeline column explicitly: state that across six realistic end-to-end pipelines the per-prediction SD is ~0.4-2.9% of label SD, rising to 8-42% only under full orbit diversity. If the authors wish to argue real cross-toolkit variation approaches the orbit (because different toolkits pick different canonical tautomers), they should measure it directly (e.g. RDKit vs OpenBabel/ChemAxon/alternative tautomer canonicalizers) rather than substituting the maximally-diverse orbit as a proxy.
- **Requires new experiment:** False

### [MAJOR] 'Comparable to a fraction of assay noise' is not defensible for realistic choices
- **Issue:** Section 6.4 claims the effect 'corresponds to prediction shifts on the order of a few tenths of a log unit - comparable to a fraction of experimental assay noise.' In absolute units this holds only for the orbit SD on sensitive models (lgbm/ecfp orbit ~0.17 log, linear/ecfp ~0.64 log). Under realistic named pipelines the SD is ~0.009-0.034 log units - roughly 2-10% of typical ChEMBL assay reproducibility (~0.3-0.5 log SD) - i.e. negligible, not 'a few tenths' and not meaningfully 'comparable to a fraction of assay noise.' No assay-noise magnitude is cited anywhere, so the comparison is unquantified.
- **Evidence:** Computed absolute log-unit SDs from method_results.csv (label_sd median 1.184 log units for lgbm/ecfp reg): orbit abs median 0.169, pipeline abs median 0.0092; linear/ecfp orbit abs 0.643. Manuscript 6.4 makes the 'few tenths / fraction of assay noise' claim without distinguishing orbit from pipeline and without a numeric assay-noise reference.
- **Fix:** Cite a concrete assay-noise SD (e.g. Kramer et al. / Landrum & Riniker ~0.3-0.55 log for ChEMBL pChEMBL) and state the comparison separately: orbit-worst-case is a sizable fraction of assay noise, realistic-pipeline is ~an order of magnitude below it. Remove the blanket 'few tenths of a log unit' characterization for the realistic scenario.
- **Requires new experiment:** False

### [MODERATE] 'Up to 0.42x' leads with a model the paper itself deprecates
- **Issue:** The abstract and Section 6.4 foreground 'up to 0.42x for fingerprint-based linear models' as the headline upper bound, but this is the linear+ECFP combination the paper elsewhere characterizes as a 'high-variance' learner it does not recommend (Section 7.2 recommends test-orbit universally and train-aug only for robust tree learners). The best-practice representation (gradient-boosted trees) has orbit SD 0.084-0.119x (and ~0.009 log units under realistic pipelines). Leading with the worst, non-recommended configuration inflates the perceived practical magnitude, and part of the 0.42x may reflect poor conditioning/extrapolation of an unregularized linear model on sparse fingerprints rather than a chemistry-driven signal.
- **Evidence:** metrics.json RQ5_invariance: linear/ecfp orbit_mean_rel_sd 0.4247 vs lgbm/desc 0.0843, lgbm/ecfp 0.1191, linear/desc 0.0715. Section 7.2 explicitly flags the high-variance linear-on-fingerprint learner as the one SORB train-aug can destabilize.
- **Fix:** Lead the magnitude statement with the robust/best-practice (tree) number and present 0.42x explicitly as a worst case for a high-variance, non-recommended model; note whether model regularization reduces the linear+ECFP spread, to separate representation sensitivity from estimator instability.
- **Requires new experiment:** False

### [MODERATE] Orbit-size / tautomer-count sensitivity (the magnitude's main knob) not run
- **Issue:** Section 8 states 'The orbit size and tautomer-count hyperparameters are varied in a sensitivity analysis (Table S4) without changing the qualitative conclusions.' The headline orbit SD is mechanically increasing in max_tautomers/max_members (more enumerated tautomers widen the orbit), so this sensitivity is exactly what determines whether 0.10-0.42x is an artifact of the chosen M=6/max_tautomers=4. No such sweep exists in results, and Table S4 is an empty SI placeholder.
- **Evidence:** OrbitConfig defaults max_tautomers=4, max_members=8 (standardize.py:218-226); run_method_cell uses test_orbit=6 (invariance.py:70). grep for orbit-size/tautomer sweeps in code/results returns only run-meta and logs, no sweep data; supplementary.md S7 names Table S4 but is unfilled.
- **Fix:** Run the pre-registered orbit-size and tautomer-count sweep and report how orbit SD scales with M and max_tautomers; if the magnitude grows with orbit size, state the headline number at a fixed, justified orbit definition and show the trend. Otherwise remove the Table S4 claim.
- **Requires new experiment:** True

### [MINOR] Seed count misstated; weakens the magnitude CIs
- **Issue:** Section 5 states 'Each configuration is run with five seeds,' and the pre-registration specified R=5 (R=10 for headline SORB/RQ2). The production grid ran only 3 seeds (0,1,2), and Section 7.1 inconsistently says 'three seeds.' Fewer seeds widen the confidence intervals on the magnitude estimates and the robustness of the medians.
- **Evidence:** grid.py:29-30 seeds=[0,1,2]/method_seeds=[0,1,2]; all result CSVs contain only seeds {0,1,2}. Manuscript line 211 says 'five seeds' while line 294 says 'three seeds'.
- **Fix:** Correct Section 5 to three seeds for internal consistency, or run the pre-registered five (ten for headline) and update all statistics; report CIs on the per-representation orbit/pipeline SD medians.
- **Requires new experiment:** False
