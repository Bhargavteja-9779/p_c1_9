# Review 03: R3-experimental (Experimental Design & Fairness)

**Recommendation:** major_revision

**Summary:** The core experimental scaffold is thoughtful, and the central design choice the paper hangs its causal claim on — computing one split on the raw structures and reusing it unchanged across every standardization pipeline — is sound and a genuine strength: it holds data partition, duplication and leakage constant so that only featurization varies. However, several design and fairness problems inflate or confound the headline results. The marquee per-prediction effect size (0.42x/0.10x of label SD) is measured over an artificial standardization "orbit" (which includes rank-2/3 enumerated tautomers and isolated stereo-stripping), while the realistic end-to-end pipeline-to-pipeline per-prediction spread that actually corresponds to "two labs standardizing differently" is ~0.03x in the same data and is never surfaced. The flagship "representation-dependent" ranking (linear+fingerprint most sensitive) is confounded by arbitrary, untuned per-model regularization. The methods section misstates the seed count (five vs the three actually run, versus a pre-registered 5/10), silently drops a pre-registered model family (SVM) while still describing it, and the "free lunch" test-time-averaging claim rests partly on an accuracy comparison across mismatched test subsets. These are fixable but material.

## Findings

### [MAJOR] Effect-size realism (orbit vs realistic pipelines)
- **Issue:** The headline per-prediction violation (abstract + Section 6.4: median 0.10x label SD, 'up to 0.42x for fingerprint-based linear models') is the synthetic standardization-ORBIT spread (metrics.json RQ5_invariance orbit_mean_rel_sd; linear+ecfp=0.4247). The orbit (src/preprocessing/standardize.py standardization_orbit) mixes the canonical form with up to 3 rank-ordered enumerated tautomers, pH-7.4, neutral, stereo-stripped and MDL-aromaticity forms simultaneously. No single realistic named pipeline produces a rank-2/3 tautomer or an isolated stereo-strip. The quantity that actually corresponds to the paper's own motivating scenario ('two laboratories apply different but equally valid standardizations') is the spread across the six realistic end-to-end pipelines (pipe_mean_rel_sd / mean_rel_sd), which is only 0.0286 for linear+ecfp and ~0.004 for trees/descriptors — roughly 15x smaller — and is never stated in the manuscript.
- **Evidence:** metrics.json: RQ5 linear+ecfp orbit_mean_rel_sd=0.4247 but pipe_mean_rel_sd=0.0286; lgbm+ecfp orbit=0.1191 vs pipe=0.0071. The abstract/Section 6.4 present only the 0.42/0.10 orbit numbers and frame orbit members as 'different, chemically-equivalent standardizations', conflating the artificial orbit with realistic pipeline choice. The realistic figure is computed (analyze.py rq5_invariance) but omitted from the manuscript.
- **Fix:** Report the realistic per-prediction pipeline spread (pipe_mean_rel_sd) alongside, and with equal prominence to, the orbit spread in the abstract and Section 6.4; lead the practical-reproducibility claim with the ~0.03x pipeline number and clearly label 0.42x as a worst-case over the full synthetic orbit. Explicitly state that orbit members include non-canonical enumerated tautomers and isolated axis toggles that exceed any single realistic pipeline.
- **Requires new experiment:** False

### [MAJOR] Hyperparameter fairness / representation-dependence confound
- **Issue:** No hyperparameters are tuned (src/models/zoo.py: Ridge alpha=1.0, LogisticRegression C=1.0 on 2048-bit ECFP with StandardScaler(with_mean=False); LightGBM 400 trees; RF 200 trees — all fixed). Holding them fixed ACROSS pipelines is correct and isolates standardization, but the paper's Contribution 2 is a cross-MODEL mechanistic claim ('linear+fingerprint most sensitive, tree ensembles least'), and that ranking is confounded with each model's arbitrary, non-comparable regularization. alpha=1.0 is weak for a 2048-dim sparse space, so an under-regularized linear model will be hypersensitive to which fingerprint bits flip under tautomerization — the observed 0.42x may reflect under-regularization, not representation. This is corroborated by the catastrophic train-augmentation failure for linear+ecfp (statistics.json: mean RMSE change -3.29, CI to -6.41, i.e. multiples of the label SD), which the manuscript downplays as a 'small accuracy cost'.
- **Evidence:** zoo.py fixed alpha=1.0/C=1.0; statistics.json linear/ecfp/reg sorb_trainaug mean_improvement=-3.289, ci_lo=-6.41 (RMSE increase of several label SDs) vs lgbm/ecfp/reg trainaug median -0.015. Such instability is a regularization pathology, not a property of 'fingerprint representation' per se.
- **Fix:** Add a robustness check in which each base learner's key regularization hyperparameter is selected by nested CV on the training fold (still identical across pipelines/orbit), and re-report the representation-dependence ranking and the trainaug accuracy cost. If the linear model's sensitivity shrinks with proper regularization, reframe Contribution 2 accordingly.
- **Requires new experiment:** True

### [MAJOR] Seed count misreport + deviation from pre-registration
- **Issue:** Section 5 (Statistics) states 'Each configuration is run with five seeds', but the full-mode grid runs three seeds (src/training/grid.py seeds/method_seeds/shortcut_seeds=[0,1,2]; confirmed in raw_results.csv and method_results.csv: seeds {0,1,2}). Section 7.1 separately says 'three seeds', so the manuscript is internally contradictory. The pre-registration specified R=5 scaffold resplits for the full grid and R=10 for the headline SORB and RQ2 comparisons; neither was met, and the reduction is undisclosed.
- **Evidence:** manuscript_filled.md Section 5 'five seeds' vs Section 7.1 'three seeds'; grid.py full mode seeds=[0,1,2]; research_plan.md 'Repeats: R = 5 ... R = 10 for the headline SORB and RQ2 comparisons'.
- **Fix:** Correct Section 5 to the actual count and reconcile with Section 7.1. Disclose the deviation from the pre-registered 5/10 repeats and justify it, or run the pre-registered number of repeats for at least the headline SORB and RQ2 analyses.
- **Requires new experiment:** True

### [MAJOR] Dropped model family / misdescribed setup (SVM)
- **Issue:** Section 5 describes 'four model families: gradient-boosted trees (LightGBM), random forests, an RBF-kernel SVM via Nystrom approximation, and a linear model', but the SVM is never run (grid.py MODELS=['lgbm','rf','linear'] with comment 'svm(Nystroem) dropped: costly, least informative'). The abstract and Contributions correctly say '3 model families', so Section 5 describes a model that produced no results. The pre-registration listed a 5-family zoo including SVM; dropping it as 'least informative' is a post-hoc selection not disclosed in the paper.
- **Evidence:** manuscript Section 5 lists the Nystrom SVM in detail; zoo.py still defines 'svm' but grid.py excludes it; research_plan.md model zoo includes 'ECFP4+SVM(RBF)'. The drop and its post-hoc rationale appear only as a code comment.
- **Fix:** Either restore the SVM to match the pre-registered zoo, or remove it from Section 5, state plainly that it was dropped, and give a pre-specified (not results-dependent) reason. Do not describe an unrun model in the experimental setup.
- **Requires new experiment:** True

### [MAJOR] Mismatched test sets in the test-orbit accuracy comparison
- **Issue:** The central safety claim — SORB-testorbit is 'a free reliability improvement ... accuracy essentially unchanged (median -0.0001 RMSE, p=0.8)' — is computed from a non-comparable paired difference. In run_method_cell (src/training/invariance.py), baseline and sorb_trainaug accuracy use the FULL test set (y[te]), while sorb_testorbit and sorb_full use a capped random subsample (ACC_CAP=600: y[cap]). For the 6 method datasets with test>600 (lipophilicity x2 ~840; CHEMBL234/214/233/244_Ki 619-731), the baseline-vs-testorbit delta mixes the averaging effect with a full-vs-subsample difference. The added sampling noise inflates variance and biases the Wilcoxon toward the null the paper reports (accuracy-neutral), so the 'free lunch' conclusion is partly an artifact of evaluating on different molecules.
- **Evidence:** invariance.py: baseline/trainaug use predict_scores(...Xcanon[te]...) on full te; testorbit/full use est.predict(cap_smi,...) with cap<=ACC_CAP=600 (ACC_CAP defined line 24). 6/49 method datasets have 0.2*n>600 (verified). analyze.py method_pooled/rq4_method pair baseline vs variant per dataset without reconciling the subset mismatch.
- **Fix:** Evaluate baseline and ALL SORB variants on the identical (capped) set of test molecules for every dataset, then recompute the testorbit/full accuracy deltas and p-values. This is a cheap re-evaluation on cached predictions.
- **Requires new experiment:** True

### [MODERATE] 6000-molecule cap biases where the method is tested
- **Issue:** All method (RQ4/RQ5) and shortcut (RQ5b) experiments exclude the 6 largest datasets via METHOD_MAX_N=6000 (run_all.py): cyp2d6/cyp3a4/cyp2c9_veith (~12-13k), solubility_aqsoldb (~10k), ld50_zhu (~7.4k), ames (~7.3k). These large, drug-like CYP/solubility/toxicity sets are exactly the kind the paper's own mechanism (RQ3: effect scales with ionizable/tautomerizable fraction) predicts should show the LARGEST invariance violation, so SORB is never evaluated where the problem is biggest. It also leaves the classification method evidence resting on only 9 (smaller) datasets, where SORB's effects are already mostly non-significant. The cap is justified only on memory grounds, which is weak for a study that states the complete run finishes in 'a few hours' on 4 CPU cores.
- **Evidence:** run_all.py METHOD_MAX_N=6000 and the 6 excluded datasets (verified sizes); RQ4 clf n_datasets=9 (statistics.json); RQ3 attributes effect to tautomer/ionization, which is high in CYP/solubility sets. Section 9 claims building orbits for the largest dataset (13,130 mols) 'takes under a minute'.
- **Fix:** Run the method/shortcut experiments on the 6 excluded datasets (chunk orbit construction / stream featurization to bound memory), or at minimum report invariance-violation magnitude for them so readers can see whether the excluded sets are the most-affected. State the exclusion and its potential bias explicitly in Section 5.
- **Requires new experiment:** True

### [MODERATE] Limited split diversity across seeds
- **Issue:** The scaffold split (src/data/splits.py scaffold_split) only randomizes tie-breaking among equal-sized scaffold groups; large scaffold groups are deterministically assigned to train regardless of seed. For datasets dominated by a few large scaffolds, the 'different' seeds yield nearly identical partitions, so cross-seed statistics understate true split variability and per-dataset CIs/variance can be optimistic.
- **Evidence:** Measured test-set Jaccard across seeds 0/1/2: molnet:esol = 0.88 (near-identical splits), tdc:bbb_martins = 0.35, mace:CHEMBL214_Ki = 0.47. splits.py order=sorted by (-len, rng.random()) only breaks size ties.
- **Fix:** Use genuinely independent resampled scaffold splits (randomize scaffold-group-to-fold assignment to the target train fraction rather than only tie-breaking), or report Monte-Carlo scaffold cross-validation, and include the per-dataset cross-seed split-overlap diagnostic so readers can judge replication independence.
- **Requires new experiment:** True

### [MODERATE] Scope of 'representation-agnostic' / 'representation-dependent' claims
- **Issue:** Both the mechanistic claim (violation is 'strongly representation-dependent') and the method claim ('representation-agnostic' SORB) are supported by only two featurizations (2048-bit ECFP4 and a 25-dim RDKit descriptor set) and two-to-three model families; no graph neural network or pretrained/learned representation is evaluated. The Limitations section discloses this, but the abstract/Contributions wording is stronger than the evidence base.
- **Evidence:** grid.py method_feats=['ecfp','desc']; method_models=['lgbm','linear']; Limitations (iv) acknowledges no GNN/pretrained models. 'Representation-agnostic' is asserted from 2 fixed representations.
- **Fix:** Soften the wording to 'across the fingerprint and descriptor representations tested', or add at least one additional, qualitatively different representation (e.g., a count-based or hashed descriptor, or a small CPU GNN) to substantiate the agnosticism claim.
- **Requires new experiment:** False

### [MINOR] Shortcut experiment control (training-set size confound)
- **Issue:** In the semi-synthetic shortcut experiment (src/training/shortcut.py), the SORB model is trained with train_aug=4 (4x augmented training examples) while the baseline shortcut model is trained on 1x data. SORB's resistance to the shortcut is therefore partly confounded with more training data / augmentation regularization, not solely with decorrelating the standardization state from the label.
- **Evidence:** shortcut.py: SORB(... train_aug=train_aug=4 ...) vs baseline ms fit on single-presentation Xtr_short. The headline comparison baseline_shortcut_drop vs sorb_shortcut_drop (metrics.json RQ5b) does not match data volume.
- **Fix:** Add a size-matched control (e.g., baseline trained on 4x copies of the shortcut presentation, or SORB with train_aug=1 plus orbit sampling) so the difference is attributable to shortcut decorrelation rather than data volume.
- **Requires new experiment:** True

### [MINOR] Inconsistent orbit hyperparameters across code paths
- **Issue:** Default orbit settings differ across entry points: OrbitConfig defaults are max_tautomers=4/max_members=8 (standardize.py), run_sorb_cell uses test_orbit=8, run_method_cell uses test_orbit=6, while the actual run pins ORBIT_CFG(max_tautomers=3, max_members=6) in run_all.py and the manuscript states M=6. Although the pinned config governs the reported run, the divergent defaults are a reproducibility/clarity hazard and make the manuscript's 'orbit bounded to M=6' statement depend on a single call site.
- **Evidence:** standardize.py OrbitConfig(max_tautomers=4, max_members=8); harness.run_sorb_cell test_orbit=8; invariance.run_method_cell test_orbit=6; run_all.py ORBIT_CFG=OrbitConfig(max_tautomers=3, max_members=6); manuscript 4.1 'M=6'.
- **Fix:** Set a single canonical OrbitConfig default equal to the reported run and remove the per-function overrides (or document them), so the manuscript's stated orbit parameters are the code defaults.
- **Requires new experiment:** False
